# R2 + R6: driving the H17, and the size of Heath's H17 BIOS

Phase 0 research for HCOS v2 (PLAN.md sections 3, 4, 8).

Sources:

- Heath CP/M 2.2.03 `BIOS.SYS`, taken from `build/disks/cpm.h8d`. Its
  sign-on is "64K HEATH/ZENITH CP/M 2.2X03 09/17/81 FOR H17 DISKS".
  The file was relocated to F000H and disassembled with a tracing 8080
  disassembler (scratch: `.../scratchpad/h17/bios/b2.dis`).
- The H17 ROM 444-19 at 1800H (`.../scratchpad/h17/rom/r1.dis`), with
  entry names from asmx `testHdos/source/acm/h17rom.acm`.
- `H17DEF` (`acm/h17def.acm`) for the port bit names.
- The emulator's `core/devices/H17.cpp` and `core/media/H17Disk.*`.
- The asmx tree has no SY: driver source and no DISDEF for the H17
  driver. `disdef.acm` is the HDOS directory-block format. HDOS INIT
  formats through the SY driver's DC.FMT call, which isn't there, so
  the format layout on real media is **[UNVERIFIED]**.

Addresses are hex, and the BIOS addresses are the F000H-relocated ones.
Cycle counts are Z80 T-states, because the H89's CPU is a Z80 at
2.048 MHz and the emulator counts Z80 T-states (`kCpuHz = 2048000`).
A `DCR A / JNZ` delay loop takes 14 T per pass (it would be 15 on an
8080).

## 1. BIOS.SYS file format (PRL)

`BIOS.SYS` is an MP/M-style **PRL** (page-relocatable) file, 4608 bytes:

| Offset | Contents |
|---|---|
| 0000H | 00 |
| 0001H-0002H | code length, 0EB4H (3764) |
| 0003H-007FH | zeros |
| 0080H-00DFH | a small relocating loader. It is assembled to run at 0200H (`LXI SP,0200H`, `LHLD 0201H`) and is not needed by HCOS |
| 0100H-0FB3H | code, assembled at 0000H |
| 0FB4H-118AH | relocation bitmap, (length+7)/8 = 471 bytes. Bits are taken MSB first, one bit per code byte. A set bit means "add the load page to this byte". There are 719 relocations |
| 118BH-11FFH | zero padding to a multiple of 512 bytes (4608) |

This was checked as follows. The first bitmap byte, 24H, flags code
bytes 2 and 5, the high bytes of `JMP 0C41H` and `JMP 0096H`. Adding F0H
to every flagged byte gives a jump table that points into F000H-FEB3H.

## 2. Ports 7CH-7FH (174Q-177Q)

The controller is the H-88-1 (H17). It has a USRT and drive-control
logic. Equate names below are from H17DEF.

| Port | Dir | Bit | H17DEF | Meaning | Emulator |
|---|---|---|---|---|---|
| 7CH | IN | 0-7 | UP.DP | received byte | Bytes are indexed by time from the sync mark. Byte 0 is the sync byte (FDH) itself. Reading late skips bytes, because overrun isn't flagged. Before sync, or with the motor off, a read returns 0 |
| 7CH | OUT | 0-7 | UP.DP | byte to transmit | Ignored unless the write gate is on. While it is on, the byte is queued, and TBE goes busy for 128 T |
| 7DH | IN | 0 | UF.RDA | receive data available | Set when a new byte index is reached since the last 7CH read |
| | | 1 | UF.ROR | receiver overrun | always 0 |
| | | 2 | UF.RPE | parity error | always 0 |
| | | 6 | UF.FCT | fill character transmitted | always 0 |
| | | 7 | UF.TBE | transmitter buffer empty | 1 while no more than one byte is still pending |
| 7DH | OUT | | UP.FC | fill character | ignored |
| 7EH | OUT | | UP.SC | sync character (always FDH) | ignored (the format is fixed at FDH) |
| 7EH | IN | | UP.SR | sync reset: start a search for sync | Arms the search for the next sync mark (header or data) that passes the head after now. If the track has no recorded sync marks, the search is not armed |
| 7FH | IN | 0 | DF.HD | hole detect (sector or index) | 2 ms pulse (4096 T). Shown only when a drive is selected, the motor is on and a disk is loaded |
| | | 1 | DF.T0 | track 0 | the selected drive's head is on track 0. Shown even with the motor off |
| | | 2 | DF.WP | write protect | 1 if the disk is read-only, no disk is loaded, or no drive is selected |
| | | 3 | DF.SD | sync detected | set once the armed sync mark has passed the head |
| 7FH | OUT | 0 | DF.WG | write gate | Rising edge clears the write buffer. Falling edge commits the write (see 3.4) |
| | | 1 | DF.DS0 | select drive 0 | If more than one bit is set, the lowest one wins |
| | | 2 | DF.DS1 | select drive 1 | |
| | | 3 | DF.DS2 | select drive 2 | |
| | | 4 | DF.MO | motor on (all drives) | needed for holes and data |
| | | 5 | DF.DI | step direction, 1 = in (toward higher tracks) | |
| | | 6 | DF.ST | step pulse (active high) | Each rising edge moves the head one track, clamped to 0..max(39, tracks-1) |
| | | 7 | DF.WR | "write enable RAM" | ignored. The ROM preserves it. Its effect on the H89 is **[UNVERIFIED]** |

**What the emulator does not model:** step rate, head settle, motor
spin-up, the speed of writes (the bytes are only queued), write
splices, a second side, and USRT overrun or parity errors. The step
pulse length doesn't matter either, as long as the bit goes 0 then 1.

**What it does enforce:** read timing. Each byte is available for one
128-T slot. The positions of the holes and sync marks are also fixed.

## 3. Disk format and timing

### 3.1 Layout

The disks are hard-sectored 5.25", with 10 sector holes plus one index
hole. The media spins at 300 rpm (200 ms per turn, 20 ms per sector),
and the data rate is 128 kbit/s. That is 16000 bytes/s, one byte every
62.5 µs, or 128 T. The disk image is 40 × 10 × 256 bytes (102,400) for
single-sided 40 tracks.

Each sector, in the emulator, counted in byte times from the leading
edge of its hole (320 bytes per sector):

| Byte | Content |
|---|---|
| 0-9 | gap (zeros) |
| 10 | FDH header sync |
| 11-14 | volume, track, sector (0-9), header checksum |
| 15-24 | gap |
| 25 | FDH data sync |
| 26-281 | 256 data bytes |
| 282 | data checksum |
| 283-319 | gap |

The index hole lies halfway between the holes for sectors 9 and 0. Each
hole is 2 ms (32 byte times), so in the emulator both sync marks pass
while the hole is still showing. The gap lengths on real disks, as
written by HDOS INIT or CP/M FORMAT, are **[UNVERIFIED]**. The
emulator's choice of 10 and 25 is the constraint HCOS is tested against.

### 3.2 Checksum

The checksum is the same in the ROM's R.RDB/R.WNB, in the BIOS and in
the emulator. It starts at 0 after the sync byte, and for each byte:
`D = RLC(D XOR byte)`. The header checksum covers volume, track and
sector. The data checksum covers the 256 data bytes.

```
RDB:  IN 7DH / RAR / JNC RDB    ; wait RDA
      IN 7CH / MOV E,A / XRA D / RLC / MOV D,A / MOV A,E / RET
```

### 3.3 Volume numbers

The header's volume byte works differently in the three sources:

- **HDOS** keeps the disk's volume in its label (track 0 sector 9,
  byte 0). It writes that volume into every header except those on
  track 0, which are 0.
- **The ROM** checks the volume. R.LPS compares it against the
  per-drive volume byte at 20A9H+2n+1 (via pointer 20A7H). R.READR
  points 20A7H at a ROM zero byte (19D0H), so it reads with volume 0,
  as the label read does.
- **The Heath CP/M BIOS ignores it.** The byte is read into the
  checksum and never compared.
- **The emulator** generates headers with volume 0 for non-HDOS
  images. For HDOS images it uses the label's volume. A reformatted
  track keeps the volume that was written into its headers.

A sector write rewrites only the data block, so the header and its
volume number stay as they are. An HCOS driver that ignores the volume
therefore reads and writes both CP/M and HDOS disks.

### 3.4 Finding, reading and writing a sector (the common algorithm)

The ROM and the BIOS share these primitives almost byte for byte:

| Step | ROM | BIOS | What it does |
|---|---|---|---|
| Wait for a sector hole (not the index hole) | R.STS 1E75H | F770H | EI. If a hole is showing, or one starts within 5 ticks (10 ms), it may be the index hole. Wait for that hole to end, then 7 more ticks (14 ms). Then DI and wait for the next hole's leading edge, then delay 20 loops (280 T) |
| Arm sync and wait for it | R.WSC 1EC7H | F7BCH | `OUT 7EH,FDH` / `IN 7EH`. Poll 7FH bit 3 up to 80 times (about 3400 T, 26 bytes). Then read 7CH (the sync byte) and set D=0. The BIOS adds 48 loops (672 T) before arming |
| Find a header | R.LPS 1DD1H | F732H | DI. Arm sync, then read volume, track, sector and checksum. On a mismatch, wait for the next sector hole and retry, 20 times (2 turns) at most. The first try doesn't wait for a hole |
| Read the data | R.READ 1C3FH | F545H | Right after the header: arm sync, read 256 bytes into the buffer, read the checksum and compare. Then EI |
| Write the data | R.WRITE 1CDEH | F57AH | Check WP. Find the header. Delay 20 loops, then 16 loops (R.WSP), then turn the write gate on. Write 10 zero bytes, FDH, the 256 bytes, the checksum, and 3 pad bytes so the last real byte leaves the shift register. Then write gate off |
| Write a byte | R.WNB 1EFBH | F7F2H | Poll 7DH bit 7 (TBE), `OUT 7CH`, update the checksum |
| Step | R.MAI/R.MAO 1DA9H | F703H/F708H | Output the shadow with the DI bit, then with the ST bit (pulse), then without. Wait N ticks of the 2 ms counter: 15 ticks = 30 ms in both |
| Seek track 0 | R.STZ 1EACH | F6F4H | Step out until T0 |

**The emulator's commit step.** When the write gate drops, the emulator
scans the bytes written for FDH. If a header follows (with the right
track and a good checksum) it is a format write, and the header's
volume and sector are taken from it. Otherwise the 256 bytes after the
FDH go to the sector in whose 20 ms slot the write gate went on. So a
sector write has to start inside the slot of the sector whose header
was just read. Both drivers start at about byte 17-20 of the slot.

### 3.5 Timing constraints (what must be cycle-counted)

| Item | Budget | Heath code |
|---|---|---|
| Read loop, per byte | under 128 T. The emulator drops a byte if the next 7CH read is a slot late | about 104 T plus polling (CALL RDB, MOV M,A, INX, DCR B, JNZ) |
| Write loop, per byte | under 128 T to keep the USRT fed. The real hardware would send fill bytes **[UNVERIFIED]**. The emulator doesn't check this | about 111 T plus polling |
| Hole to sync armed (header) | The emulator's header sync is at byte 10 (1280 T after the hole). Arming later than that catches the *data* sync, which reads as a header mismatch and costs a retry | ROM: about 400 T (byte 3). **BIOS: about 1085 T (byte 8.5), a margin of only about 1.5 bytes.** Computed, not measured |
| Header end to data sync armed | before byte 25 | both are well inside |
| Interrupts | Must be **off** from arming the header sync to the end of the data. The 2 ms ISR alone (about 100 T) takes most of a byte time | DI in LPS, EI after the transfer. Up to about 20 ms of clock ticks can be lost per attempt. The console type-ahead ISR (RST 3) is blocked too |
| Gap before the write gate | 20+16 loops after the header checksum | fixed delays |

### 3.6 Mechanical timing used by Heath

These figures come from the code. The tick is the 2 ms clock.

| Parameter | ROM (constants at 2048H-2055H, copied from 1F5AH) | BIOS |
|---|---|---|
| Step rate | 204DH = 0FH, 15 ticks = 30 ms | drive-extension byte 5, bits 0-6 = 0FH, 30 ms |
| Motor spin-up (motor was off) | 2050H = FAH, 250 × 4 ms = 1 s | FAH × 4 ms = 1 s. If byte 5 bit 7 is set, 3EH × 4 ms = 248 ms |
| Select or head-load delay | 204FH = 11H, 68 ms, if idle for more than 8 ms | changing drive with the motor on: 14H × 4 ms = 80 ms |
| Head settle after a seek | none, apart from the step wait | at least 6 × 4 ms = 24 ms before every operation (F6E5H). It is counted in sector holes, so in practice the operation lands on the next suitable header |
| Motor off | 20A3H = 78H, 120 × 512 ms ≈ 61 s | F81EH = 0FH, 15 × 512 ms ≈ 7.7 s |
| Deselect | with the motor off (ANI 80H) | F81FH = 06H, 6 × 512 ms ≈ 3 s, clears DS0-DS2 |
| Retries | 10 (20B4H). R.CDE **re-zeros and re-seeks on every error** | 10 (FE26H), with the head jiggle described below |
| Sector-find attempts | 20 (204EH) | 20 |
| Ready check | none | at login: count hole edges for 100 ticks (200 ms). It needs 20-24 (11 holes per turn = 22 edges), else error 80H |

`H17DEF` also gives `H17SDL` = 900 µs: drives other than Wangco need
that delay after a write before a step. Neither driver applies it
explicitly; the gap between operations is longer anyway.

## 4. Heath's H17 BIOS, annotated

### 4.1 Page zero and fixed RAM it relies on

| Addr | Use |
|---|---|
| 0000H / 0005H | JMP F003H (WBOOT) / JMP E206H (BDOS) |
| 0003H / 0004H | IOBYTE (default from F034H = A9H) / current disk |
| 0008H | JMP F821H, the 2 ms clock ISR (RST 1) |
| 000BH-000CH | the 2 ms tick counter (16-bit) |
| 000DH | shadow of port F2H. The ISR re-outputs it every tick |
| 000EH | shadow of port F0H (H8 front panel). 0 on the H89, and then F0H is never touched |
| 000FH | **shadow of H17 port 7FH** |
| 0018H | JMP F9A8H, the console receive ISR (RST 3, type-ahead) |
| 0040H-0047H | logical drive → physical DPH index map (SELDSK) |
| 0048H-0049H | boot device type and port, left by the boot loader (R1) |
| 004EH | 0F000H, the BIOS address, for utilities |

Heath keeps its data in 000BH-000FH, in the RST 1 slot after its JMP.
A program that uses RST 1 space would break the disk driver.

### 4.2 Entry points and structure

| Entry | Addr | Notes |
|---|---|---|
| BOOT | FC41H | Lives in the host-buffer area and is overwritten later. DI, SP=FF12H. Installs RST 1 and RST 3 and sets up the 8250s from the port table. Detects an H8 8251 console at FAH/FBH only if 000EH ≠ 0. Prints the sign-on, builds the drive map 0040H, then JMP F12AH |
| WBOOT | F096H | SP=FF12H, EI, SELDSK 0 (full login). Reads 44 records through the BIOS's own SETTRK/SETSEC/READ and XLT to D980H, keeping only those that land in DA00H-EFFFH, so CCP+BDOS is DA00H-EF7FH. Sets 0000H and 0005H, DMA 80H, then JMP DA00H or DA03H. On error: "ERROR DURING WARM BOOT - PRESS ANY KEY", then retry |
| CONST..READER, LISTST | F8D4H-F946H | IOBYTE dispatch: each entry rotates the IOBYTE and indexes an inline 4-word table (F955H) |
| HOME | F177H | DRI style: if !hstwrt then hstact=0; track 0 |
| SELDSK | F18AH | C ≥ 3 → HL=0. Maps through 0040H. DPH = F04EH + 24·n. On first login (E bit 0 = 0) it flushes the host buffer, runs the mount check, then calls the driver's *login* (ready and speed check) |
| SETTRK/SETSEC/SETDMA | F212H-F21DH | SETSEC stores sector-1 (0-based) |
| SECTRAN | F21EH | XLT=0 → BC+1, else XLT[BC] (1-based values) |
| READ/WRITE | F22BH/F23FH | DRI blocking/deblocking (below) |

### 4.3 Drive table (DPH + 8-byte extension, 24 bytes per drive)

DPH n is at F04EH + 24n (F04EH, F066H, F07EH):

| DPH field | A: | B: | C: |
|---|---|---|---|
| XLT | FC2AH | FC2AH | FC2AH |
| DIRBUF | FD41H | FD41H | FD41H |
| DPB | FC1BH | FC1BH | FC1BH |
| CSV / ALV | FDCDH / FDC1H | FDE9H / FDDDH | FE05H / FDF9H |

The 8-byte Heath extension follows each DPH, at DPH+16:

| Byte | A: | B: | C: | Meaning |
|---|---|---|---|---|
| 0 | 40H | 40H | 40H | bits 7-5 = driver index into F202H (2 = H17, others → null driver F800H) |
| 1 | 02H | 04H | 08H | port 7FH drive-select bit |
| 2 | 02H | 02H | 02H | 128-byte records per physical sector |
| 3 | 08H | 08H | 08H | records per block (initial unacnt) |
| 4 | FFH | FFH | FFH | current track. Bit 7 means unknown, so the next operation seeks track 0 first |
| 5 | 0FH | 0FH | 0FH | step time in 2 ms ticks; bit 7 = short (248 ms) motor spin-up |
| 6 | 00H | 00H | 00H | bit 1 = one physical drive shared by two logical drives (mount prompt) |
| 7 | 00H | 00H | 00H | logical drive currently mounted (used by the prompt) |

Driver vector (F4F8H), called as F1F0H with DE = 0, 3, 6, 9 or 12:
login F636H, read F507H, write F520H, reset/off F629H (all off, control
port 0), and "track unknown + off" F620H.

### 4.4 DPB and XLT (the only H17 format this BIOS supports)

There is **one DPB, shared by all three drives: single-sided, 40
tracks, 10 × 256.** There is no DS or 80-track format in this BIOS. The
emulator doesn't model a second side either.

| Field | Value |
|---|---|
| SPT | 20 (records/track) |
| BSH / BLM / EXM | 3 / 7 / 0 (1K blocks) |
| DSM | 91 (92K: 37 tracks × 2.5K = 92.5K) |
| DRM | 63 (64 entries) |
| AL0 / AL1 | C0H / 00H (2 directory blocks) |
| CKS | 16 |
| OFF | 3 (system tracks 0-2) |

The XLT (FC2AH, 20 bytes, 1-based records) is
`1,2,9,10,17,18,5,6,13,14,3,4,11,12,19,20,7,8,15,16`. Records stay in
pairs within each 256-byte sector. Logical sectors 0-9 map to physical
sectors **0,4,8,2,6,1,5,9,3,7**, so consecutive logical sectors are
4 sectors (80 ms) apart, and the BDOS, deblocking and the 24 ms settle
have time to finish between them.

### 4.5 Deblocking (F23FH-F418H)

This is DRI's DEBLOCK algorithm (hstact, hstwrt, unacnt with
unadsk/unatrk/unasec, wrtype 0/1/2), generalized by extension byte 2
(records per sector):

- Host sector = record >> log2(rps).
- Offset = (record & (rps-1)) × 128.
- Host buffer `HSTBUF` = FC41H, 256 bytes.
- The 128-byte move is LDIR on a Z80 and a loop on an 8080. The CPU is
  detected at F8BFH with `MVI A,81H / ADI 80H / JPO`.
- The unallocated-write path inverts the XLT by searching it, so that
  it can follow the sequence.
- wrtype 1 (directory) writes through at once.
- An error clears hstact.

### 4.6 The H17 driver (F4F8H-F7FFH, 776 bytes)

| Routine | Addr | Function |
|---|---|---|
| read / write front ends | F507H / F520H | copy hsttrk/hstsec into FE21H/FE22H, call the core, set the error flag FE37H |
| done | F539H/F53AH | DI, motor-off timer 0FH, deselect timer 06H, EI |
| read core | F545H | prepare, seek, find header, data sync (20H on failure), 256 bytes into HSTBUF, checksum (08H on failure) |
| write core | F57AH | WP (40H), prepare, seek, find header, write (3.4) |
| error/retry | F5C8H | EI. Error count +1 (16-bit, at F049H). 40H/80H are fatal at once. Retries count down from 10. On 01H (wrong track), or when 5 retries are left, restore to track 0. On even retries, jiggle the head one track in or out (never past 0 or 39) to force a re-seek. On odd retries, just retry. A fatal error prints "H17 READ/WRITE ERROR nn" (F419H, if F036H bit 1) and returns CY |
| login | F636H | select, wait for the motor timer, count hole edges for 200 ms (needs 20-24) |
| select/motor | F674H | Stop the auto-off timers. OUT the select bits + MO. Set the delay timer F820H to 1 s (motor was off), 80 ms (other drive), or 0 |
| prepare | F6B5H | select, retries=10, seek track 0 if the track is unknown |
| seek | F6D1H | step to FE21H, then set the minimum settle (F820H ≥ 6) |
| restore | F6F4H | step out until T0 |
| step | F703H/F708H | pulse ST, then wait byte5&7FH ticks |
| find header | F72FH-F76FH | wait until F820H = 0 (hole by hole), then up to 20 header tries with DI. Codes: 02H no sync, 01H wrong track, 10H wrong sector, 04H header checksum |
| wait for sector hole | F770H | as in 3.4 |
| byte, sync, write primitives | F7AEH-F7FFH | RDB, WSC (+48-loop delay), WSP, WNB |

**The clock ISR** (F821H, 102 bytes, every 2 ms):

- Saves HL and PSW in RAM, without switching stacks.
- Re-outputs the F2H shadow, and F0H if it is non-zero.
- Increments 000BH.
- Every 512 ms (low byte wraps): counts down F81EH (motor off: clears
  MO in 000FH and OUTs it) and F81FH (deselect: clears DS0-DS2).
- Every 4 ms: counts down F820H.

**Error codes** (FE27H): 01H track, 02H header sync, 04H header
checksum, 08H data checksum, 10H sector, 20H data sync, 40H write
protect, 80H not ready.

## 6. ROM routines vs Heath's BIOS as the model

The two are the same design: the BIOS driver is a de-vectored copy of
the ROM's (RDB, WNB, WSP, WSC, STS, MAI/MAO and STZ match almost
instruction for instruction). The ROM disk code itself is
1BCEH-1F09H, 828 bytes.

On top of that the ROM uses:

- an 88-byte RAM table at 2048H-209FH (constants plus 18 JMP vectors,
  so HDOS can patch it);
- work cells at 20A0H-20BDH;
- 201BH (MTR's tick counter);
- 201FH (the clock hook, pointed at its timer routine 1C19H);
- 2131H (the drive number).

The ROM is cleaner, but it isn't a better model:

| | ROM 444-19 | Heath BIOS |
|---|---|---|
| Interface | HDOS: linear sector 0-399, byte count, multi-sector, partial last sector | one 256-byte sector, by track/sector |
| Drives | select = (n+1)·2, so drive 2 gives 06H (DS0+DS1). **It looks like it supports only SY0/SY1** (an inference from the code) | 3, from a table |
| Volume | checked | ignored |
| Retries | re-zero and re-seek on every error | jiggle and restore; cheaper |
| RAM it needs | 2000H area (absent or TPA in CP/M mode) | page zero 000BH-000FH, 0040H-004FH, its own F-page |
| Timing safety | arms the header sync at about byte 3 | about byte 8.5, close to the emulator's byte 10 |

**ROM in vs RAM at 0000H:**

- With ORG-0 RAM, 0000H-1FFFH is RAM. The ROM and its 2000H-area
  state can't be used, and the driver must be self-contained.
- The clock comes in at 0008H. With the ROM in, it comes through the
  ROM to the 201FH vector, and the tick counter is 201BH, not 000BH.
- The ROM keeps its own 7FH shadow (20A2H), drive-track table (20A9H)
  and motor timers. An HDOS program that drives the ROM routines (R7)
  changes the head position and the motor state behind the BIOS. After
  any such program the BIOS must mark every drive's track as unknown,
  and resync its shadow from scratch.
- The driver itself needs nothing in page zero or at 2000H except a
  tick source and its shadow and timers. HCOS should keep them in BIOS
  RAM, not at 000BH-000FH as Heath does.
- Ports F0H/F1H/FAH/FBH raise an NMI on the H89 (in the emulator too),
  so the driver and clock must not touch them on the H89 (R5).

## 7. Implications for the HCOS v2 H17 driver

**Recommended design:**

1. **Interface.** `H17RD`/`H17WR` take a drive (0-2), a track, a
   sector (0-9) and a buffer, and return CY plus an error code. They
   handle one 256-byte sector. Deblocking sits above it: keep DRI's
   algorithm (hstact/hstwrt, write-through on wrtype 1). The "unalloc"
   pre-read skip saves a read per new block; keep it if the bytes
   allow, otherwise always pre-read (about 120 bytes less).
2. **Primitives.** Take them from the ROM: RDB, WNB, WSC, WSP and the
   STS hole wait with its index-hole logic. Arm the header sync as the
   ROM does, no more than about 400 T after the hole edge, *without*
   the BIOS's 48-loop pre-delay. Keep every per-byte loop under 128 T,
   counted in Z80 T-states. DI from arming the sync to the end of the
   data, EI after.
3. **Header check.** Compare track and sector and the checksum, and
   ignore the volume, so HDOS disks work. Up to 20 header tries.
4. **State in BIOS RAM.**
   - the 7FH shadow;
   - per-drive current track, with bit 7 = unknown;
   - motor-off and settle timers;
   - its own 16-bit tick counter.

   The RAM-mode handler at 0008H and a hook on 201FH (ROM mode)
   update the same counter. On every return from an HDOS program,
   mark all tracks unknown and clear the shadow (R7).
5. **Timing parameters.** One table: step 15 ticks (30 ms), motor
   spin-up 1 s, drive change 80 ms, motor off about 8 s. Skip Heath's
   24 ms settle on every operation. Settle only after an actual step,
   with 1 tick plus the "skip to the next hole".
6. **Errors.**
   - Retries: 10. On even retries jiggle the head, on 01H restore.
   - Write protect is fatal.
   - Replace the 200 ms speed check with "no hole within 2 turns →
     not ready". It is cheaper and still catches an empty drive.
7. **Formats.** SS 40-track only (the DPB and XLT in 4.4). DS/80 would
   need a side-select bit the emulator doesn't have, plus bigger
   ALV/CSV. Leave it out of 2.0.

**Byte estimate** (8080 code, 3 drives):

| Part | Bytes |
|---|---|
| Jump table | 51 |
| Disk BIOS entries (SELDSK, HOME, SETxxx, SECTRAN) | 80 |
| Deblocking | 220 |
| H17 driver (select/motor 45, seek/step/restore 80, hole wait 45, find header 55, read 45, write 65, sync/byte primitives 75, retry/error 60, not-ready 20) | 490 |
| Clock ISR (tick + 3 timers) | 45 |
| Console (8250 CONST/CONIN/CONOUT; LIST/PUNCH/READER minimal) | 70 |
| Utilities and messages | 50 |
| WBOOT (if the BIOS reloads the shell) | 100 |
| DPH × 3 + DPB + XLT + drive table | 95 |
| **Code + tables** | **~1200** |
| HSTBUF 256 + DIRBUF 128 + ALV 36 + CSV 48 + variables 40 + stack 64 | 572 |
| **Total** | **~1.8K** |

Cold-boot code can overlay HSTBUF, as Heath's does.

A minimal H17 BIOS fits in about **1.8K of the 4K**. That leaves about
2.2K at F000H-FFFFH for the H37 driver, its larger buffers and ALVs,
the memory switch and the H8 layer. That is consistent with fitting
both drivers in 4K, if the H37 side is also kept to about 1.5K plus its
buffers (R3).
